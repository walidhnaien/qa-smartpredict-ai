V3.5.3.1 — Preload and bounded transport recovery

Apply at repository root. Run mvn clean install in backend (expected 46 tests), then docker compose up -d --build backend. No migration or compose change.
Every lifecycle chat first sends empty messages to /api/chat with identical options, model and keep_alive. Ollama acknowledges done=true. This is a readiness acknowledgement, not proof that a later call cannot reload. Each HTTP read timeout remains 240s. One retry for nested socket/connect failures or HTTP 408/429/502/503/504; no retry for semantic errors or generic HTTP 500. Retry occurs inside the lifecycle lock, before persistence. Logs include phase, attempt, duration and retry. The workflow step attempt remains 1; transport attempts are in logs. No restart recovery or resource admission check in this patch. A timed-out server task may still be active; Ollama serializes requests with NUM_PARALLEL=1. Total workflow time can increase; measure all phases. Four nominal inference calls plus four preload calls; retries can add calls. Tests cover payload and classification only; integration and failure injection still required.
